## Environment prerequisites

1. Resolve the current shared Docker API/listener hang through its owner. Do not globally restart, reset, prune or stop Docker/OrbStack or other projects. Check only CaptionDoor's isolated project/ports:3410 web,3411 worker,8410 DynamoDB Local, optional3443 HTTPS. A hung local runtime is a BLOCKED result, not an excuse to replace DynamoDB with memory storage.
2. Preserve the existing local demo environment and data. Normal setup preserves records; do not use destructive reset for a provider smoke. Use an ignored/private environment file or protected runtime configuration, with0600 permissions where applicable. No credential may enter source, `NEXT_PUBLIC_`, browser storage, command-line arguments, shell history, URLs, screenshots or logs.
3. Use the currently implemented server settings: `RING_MODE=playground` plus an existing `RING_PLAYGROUND_TOKEN` for Playground; `RING_MODE=live` plus approved `RING_CLIENT_ID`, `RING_CLIENT_SECRET`, `RING_WEBHOOK_SECRET` and exact registered HTTPS `RING_REDIRECT_URI` for partner OAuth. Never put a refresh token in a Bearer header. Playground tokens do not acquire refresh capability by changing mode.
4. Select credential encryption before any media/link storage: explicit development encryption with a separately generated32-byte Base64 `DEV_CREDENTIAL_KEY`, or configured KMS encryption in production. Production requires actual OIDC/live/AWS modes and rejects demo/fixtures; do not call a local demo configuration production. No key-generation command that echoes its result is included here.
5. Ring app linking is separate from resident authentication. Use a fresh authenticated household owner with membership permissions, the selected household door and affirmative Ring consent. Audio transcription has a separate consent/grant/action. Do not request resident or visitor microphone access.
6. Leave AWS transcription and Web Push unexercised unless separately authorized. In a Ring-only smoke, do not start incoming-audio capture into the AWS worker. A video-only/no-caption outcome is valid evidence of that limited scope, not a successful caption demo.

The replay command requires no provider credential. It writes each attempt under `output/judge-replay/<UTC timestamp>-<id>/result.json`, exits2 with BLOCKED on bounded preflight failure, and records PASS only after the actual local child browser journey succeeds. Existing active demo visits must be closed deliberately first. The commands below inspect local health only and contain no credentials. They can still time out while the current runtime blocker persists:

```sh
curl --fail --max-time 8 http://127.0.0.1:3410/api/health
curl --fail --max-time 8 http://127.0.0.1:3411/health
```

There is currently no completed real-provider smoke transcript or automatic real-Ring smoke runner in this checkout. Do not invent a `smoke:ring` command or bypass authorization with direct database edits.

## Validation order after separate authorization

1. **Confirm configuration without displaying values.** Record mode, endpoint origin, credential-present booleans, browser/version and UTC start. A missing/expired token must fail visibly; no automatic LOCAL fallback is permitted.
2. **Account correlation:** use the server adapter's `getAccountId()` (`GET /v1/users/me`) and confirm the JSON:API users resource ID supplies webhook account correlation. Retain a sanitized test identifier/hash, not the raw profile or household name.
3. **Discovery/configuration:** `listDevices()` requests `GET /v1/devices?include=capabilities,status`; join status through the documented type+ID relationships. Select only an authorized door. Read `GET /v1/devices/{id}/configurations` and its boolean `e2e_encryption.enabled`. Record offline/encrypted/unknown cases honestly; never ask a user to disable encryption.
4. **Select and claim the app visit explicitly.** A Playground live-view simulation is not a verified Ring doorbell event. If no authorized visit can be created with correct event provenance, stop the full-UI media smoke as BLOCKED; do not label a locally injected event PLAYGROUND/LIVE or manufacture a visit/lease in the database. A separately approved event feeder must preserve LOCAL provenance and use the real backend validation path.
5. **Receive-only WHEP:** follow the [current WHEP contract](https://developer.amazon.com/docs/ring/api-documentation.html#whep-live-video-streaming). Register handlers before negotiation, include required video plus optional incoming audio, use `recvonly` on every track, finish ICE gathering and send SDP through the authenticated server. Credentials stay backend-only; a valid201/SDP/Location is signaling acceptance, not LIVE media. Require an actual connected peer and incoming video before the browser-ready signal. Record whether an audio track actually arrived; absence means unavailable captions.
6. **Bounded stop/fallback:** test explicit stop and the documented30-second battery/60-second line limit only if authorized; this app conservatively uses30 seconds. Observe text continuity, track/lease cleanup and provider-DELETE outcome separately. A timeout is not proof of visitor departure or observed provider closure. Cleanup credentials are access-only, scoped and short-lived; no refresh or credential resurrection is allowed after unlink.
7. **Partner-only operations remain separate:** only a specifically approved account-link test should exercise PKCE/state, code exchange, mandatory completion, rotation or unlink. Only a registered signed delivery can establish actual webhook evidence/five-second timing. Local signed fixtures cannot be reported as Ring delivery. Never trigger these account changes automatically at the end of a read-only smoke.
8. **Restore only this project's deliberate test configuration** after the operator finishes. No change to another project, shared database, system trust, provider encryption or global runtime is part of validation.

## Evidence to retain safely

Record UTC date/time, commit/build identifier, mode, operation name, HTTP success/error category, sanitized request/test ID, elapsed time, consent/action performed, actual track presence, explicit stop/cleanup result and PASS/FAIL/SKIP/BLOCKED status. Keep `eventSource`, `mediaSource` and `transcriptSource` independent. Do not retain bearer/refresh tokens, client/HMAC secrets, cookies, raw SDP/ICE details, private provider URLs, full profile/device JSON or audio/video recordings.

A future replay based on actual Ring validation must identify which sanitized observations came from a real authorized provider run, when they were obtained and which later events/media/transcripts are synthetic. CaptionDoor currently has no such captured provider evidence. Fixture replay remains useful for credential-free judging and local product inspection, but does not establish substantial actual Ring use by itself.
