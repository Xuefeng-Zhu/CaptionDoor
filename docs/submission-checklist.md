## Ring simulator interpretation and provenance

Physical Ring hardware is optional. The [event FAQs](https://amazonappdev2026.devpost.com/details/faqs) identify Ring Developer Playground as a suitable simulator. The [organizer's self-built-simulator clarification](https://amazonappdev2026.devpost.com/forum_topics/45511-ring-track-does-simulator-include-one-i-wrote-myself) also accepts a participant-built simulator when substantial actual Ring technology is used. The discussed example combined real-token API validation with simulated events through its backend. It does not establish an endpoint-count threshold or make every fixture-only project compliant.

The [Playground/mixed-footage clarification](https://amazonappdev2026.devpost.com/forum_topics/45462-simulator-on-amazon-ring) permits a clearly labeled combination of Playground streams and the participant's own scenarios. Preserve event, media and transcript provenance independently. For example, a LOCAL doorbell event, actual PLAYGROUND media and FIXTURE captions must retain those three labels; that combination is not an observed Ring doorbell-to-AWS-caption journey.

CaptionDoor currently has implemented Ring adapters, real local DynamoDB/API/socket/browser evidence and intercepted-provider tests. Its single authorized remote attempt reached official Playground discovery, but no incoming audio/video tracks or AWS final captions were observed; the exact media failure cause was not recorded. Its local simulator may form part of an acceptable mixed demonstration, but substantial actual Ring runtime evidence is still missing. An official-simulator-only requirement is not asserted here.
